## Inspect Logs in the Vm
In the vm, open eventviewer and navigate to the windows log -> Security tab to see all seurity event. 
Logout of the vm and we simulated multiple failed login attempt using a wrong user and password. we login with the correct user and password and open eventviewer and navigate to the windows log -> Security tab. Using the filter button, filter for the event 4625 to see all the failed login attempt.

## Log Forwarding to Sentinel
1. We created a Log Analytics Workspace, LAW-SOC-LAB-01


2. Create a Microsoft Sentinel instance

Search Microsoft Sentinel → Create
Click Add next to our Log Analytics Workspace LAW-SOC-LAB-01
Sentinel is now connected to our LAW

3. Configure the Windows Security Events connector (AMA)
This creates a connection: VM → Data Collection Rule → LAW → Sentinel

In Sentinel, go to Content Management → Content Hub

Note: this redirected us to Microsoft Defender

Search for Windows Security Events via AMA
Install it, then click Open connector page
Click Create Data Collection Rule (DCR)

Name: DCR-Windows
Resource group: RG-SOC-Lab
we added our VM as a resource
Select All Security Events 

Click Review + Create

4. Verify the agent installed on the VM

On our VM → Settings → Extensions + Applications
You should see Azure Monitor Agent listed
Status should show Provisioning succeeded

This confirms logs are being forwarded from the VM to the LAW.

5. Verify logs are arriving

On Log Analytics Workspace → Logs
Run this query:
in kql mode 

SecurityEvent
| where EventID == 4625
| order by TimeGenerated desc



We can see our simulated failed logins, plus other real attacks that have already hit the VM.
