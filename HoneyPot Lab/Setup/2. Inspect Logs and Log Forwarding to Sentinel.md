## Inspect Logs in the Vm
In the vm, open eventviewer and navigate to the windows log -> Security tab to see all seurity event. 
Logout of the vm and simulate multiple failed login attempt using a wrong user and password. Login with the correct user and password and open eventviewer and navigate to the windows log -> Security tab. Using the filter button, filter for the event 4625 to see all the failed login attempt.

## Log Forwarding to Sentinel
Create a Log Analytics Workspace, LAW-SOC-LAB-01

Search Log Analytics Workspaces in the portal → Create
Assign it to your resource group RG-SOC-Lab
Give it a name (e.g. SOC-LAW)
Choose the same region as your VM
Click Review + Create

2. Create a Microsoft Sentinel instance

Search Microsoft Sentinel → Create
Click Add next to your Log Analytics Workspace LAW-SOC-LAB-01
Sentinel is now connected to your LAW

3. Configure the Windows Security Events connector (AMA)
This creates a connection: VM → Data Collection Rule → LAW → Sentinel

In Sentinel, go to Content Management → Content Hub

Note: this would redirect you to Microsoft Defender

Search for Windows Security Events via AMA
Install it, then click Open connector page
Click Create Data Collection Rule (DCR)

Name: DCR-Windows
Resource group: RG-SOC-Lab
Add your VM as a resource
Select All Security Events 

Click Review + Create

4. Verify the agent installed on the VM

Go to your VM → Settings → Extensions + Applications
You should see Azure Monitor Agent listed
Status should show Provisioning succeeded

This confirms logs are being forwarded from the VM to the LAW.

5. Verify logs are arriving

Go to your Log Analytics Workspace → Logs
Run this query:

in kql mode 

SecurityEvent

you should see all the securiy logs 

SecurityEvent
| where EventID == 4625
| order by TimeGenerated desc

You should see your simulated failed logins, plus any real attacks that have already hit the VM.

It may take 5–15 minutes after DCR creation for the first logs to appear.
